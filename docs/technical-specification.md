# Техническое задание: сайт-лендинг для музыканта

## 1. Цель проекта
Создать сайт-лендинг для музыканта с удобной админкой на Django, чтобы можно было управлять всем основным контентом без правок в коде.

Сайт должен рассказывать о музыканте, показывать его образ, репертуар, контакты и публикации с фото и видео.

## 2. Целевая аудитория
Целевая аудитория сайта — люди примерно от 30 до 70–80 лет. Поэтому интерфейс должен быть:

- понятным;
- спокойным;
- крупным и читаемым;
- теплым по атмосфере;
- без перегруженных анимаций и сложной навигации.

## 3. Концепция сайта
Сайт должен создать ощущение живого и камерного выступления. Визуальная подача — теплая, уютная, с атмосферой деревянного интерьера, декоративного света и концертного настроения.

## 4. Структура публичной части
На сайте должны быть следующие блоки:

- главный экран с основной фотографией музыканта;
- имя музыканта или название проекта;
- краткое описание;
- блок с репертуаром или услугами;
- лента постов;
- контакты для связи.

## 5. Админка
В админке должны быть доступны следующие возможности:

- смена основной фотографии;
- редактирование имени или названия проекта;
- редактирование описания;
- редактирование контактов;
- создание и редактирование постов;
- изменение порядка постов;
- смена статуса поста;
- мягкое удаление и восстановление записей.

Админка нужна одна, без сложной системы ролей. Достаточно одного администратора.

## 6. Посты
Каждый пост должен содержать:

- заголовок;
- основной текст;
- медиа-блок;
- порядок сортировки `sort_order`;
- статус;
- служебные даты и поля.

Пост может содержать:

- одно фото;
- одно видео;
- карусель из фото и видео;
- набор медиа-элементов в одном посте.

Расположение поста на сайте должно быть таким:

1. Заголовок.
2. Фото, видео или карусель.
3. Основной текст.

## 7. Статусы постов
Для постов нужен поле `status`.

Рекомендуемый набор статусов:

- `draft` — черновик;
- `published` — опубликован;
- `archived` — скрыт, но не удален.

Если потребуется, `archived` можно использовать как служебный скрытый статус.

## 8. Мягкое удаление
Нужно реализовать мягкое удаление для всех основных сущностей.

Требования:

- запись не удаляется физически из базы;
- она помечается как удаленная;
- удаленные записи не отображаются на публичном сайте;
- в админке должна быть возможность восстановить запись.

## 9. Сортировка постов
Посты должны выводиться по полю `sort_order`.

Требования:

- админка должна позволять менять сортировку;
- сайт должен показывать посты в нужном порядке;
- при одинаковом `sort_order` можно дополнительно учитывать дату создания или публикации.

## 10. Служебные даты и поля
У всех основных сущностей должны храниться служебные данные:

- дата создания;
- дата обновления;
- признак удаления;
- при необходимости дата публикации;
- при необходимости дата архивирования.

## 11. Контакты
Через админку должны редактироваться основные контакты:

- телефон;
- мессенджеры;
- социальные сети;
- город или регион;
- любые дополнительные способы связи при необходимости.

## 12. Дизайн
Визуальные требования:

- теплый и камерный стиль;
- уютная атмосфера;
- крупные читаемые шрифты;
- хорошая контрастность;
- удобство для возрастной аудитории;
- акцент на фото музыканта и его образе;
- без перегруженного интерфейса.

## 13. Технический стек
Рекомендуемый стек:

- backend: Django;
- админка: стандартная Django Admin с доработками;
- база данных: SQLite на старте, PostgreSQL для продакшена;
- медиа: хранение фото и видео через Django media;
- публичная часть: Django templates.

## 14. Основные сущности проекта
Минимальный набор моделей:

- профиль музыканта или главная карточка сайта;
- контакты;
- пост;
- медиа-элементы поста.

## 15. Критерии готовности
Проект считается готовым, если:

- на сайте отображается лендинг музыканта;
- в админке можно менять основную фотографию, имя и описание;
- в админке можно создавать посты с фото и видео;
- посты сортируются по `sort_order`;
- доступны статусы `draft`, `published`, `archived`;
- работает мягкое удаление и восстановление;
- можно редактировать контакты;
- сайт выглядит тепло, понятно и аккуратно для целевой аудитории.
