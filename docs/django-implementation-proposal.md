# Предложение по реализации на Django

## 1. Почему Django подходит лучше всего
Django хорошо подходит для этого проекта, потому что:

- дает мощную встроенную админку;
- позволяет быстро управлять контентом;
- удобно реализует модели, статусы и сортировку;
- хорошо подходит для мягкого удаления;
- дает понятную структуру, которую легко контролировать, если ты уже разбираешься в Django.

## 2. Рекомендуемая архитектура
Предлагается следующая архитектура:

- Django как backend и основа проекта;
- Django Admin как панель управления;
- Django templates для публичного лендинга;
- SQLite на этапе разработки;
- PostgreSQL для продакшена;
- Django media для фото и видео.

## 3. Предлагаемые модели
Минимальный набор моделей:

### 3.1. Profile / SiteContent
Хранит основную информацию о музыканте или проекте.

Поля:

- имя или название проекта;
- описание;
- основная фотография;
- служебные поля `created_at`, `updated_at`, `is_deleted`.

### 3.2. ContactInfo
Хранит контакты для связи.

Поля:

- телефон;
- мессенджеры;
- социальные сети;
- город или регион;
- дополнительные контакты;
- служебные поля.

### 3.3. Post
Основная модель публикаций.

Поля:

- заголовок;
- основной текст;
- `status`;
- `sort_order`;
- даты создания и обновления;
- признак мягкого удаления;
- при необходимости `published_at`.

### 3.4. Media
Медиа-элементы внутри поста.

Поля:

- связь с постом;
- тип медиа: фото или видео;
- файл или ссылка;
- порядок внутри поста;
- служебные поля.

## 4. Поведение статусов
Рекомендуемые статусы:

- `draft` — не показывается на сайте;
- `published` — виден на сайте;
- `archived` — скрыт, но сохранен в базе.

Если захочешь позже, статусы можно расширить, но базового набора достаточно для запуска.

## 5. Мягкое удаление
Для мягкого удаления можно использовать общий abstract-миксин, который добавляет:

- `is_removed`;
- методы скрытия, восстановления и фильтрации активных записей.

Это позволит:

- не терять данные;
- восстанавливать записи из админки;
- исключать удаленные записи из публичного вывода.

## 6. Сортировка постов
Рекомендуется хранить `sort_order` у поста и сортировать публикации:

1. по `sort_order`;
2. при совпадении — по дате создания или публикации.

В админке стоит сделать удобную возможность менять порядок постов.

## 7. Админка
В админке должны быть:

- редактирование главной информации;
- управление контактами;
- создание постов;
- добавление фото и видео к посту;
- изменение статуса;
- изменение сортировки;
- восстановление удаленных записей.

## 8. Публичная часть
На публичной части сайта предлагается сделать:

- hero-блок с фото и описанием;
- блок репертуара или услуг;
- ленту постов;
- контактный блок;
- визуально теплую и простую подачу.

## 9. Предложение по этапам разработки
1. Создать Django-проект и основные приложения.
2. Реализовать модели профиля, контактов, постов и медиа.
3. Добавить статусную логику и мягкое удаление.
4. Настроить Django Admin.
5. Сделать публичный лендинг.
6. Добавить вывод постов по `sort_order`.
7. Проверить адаптивность и читаемость интерфейса.
